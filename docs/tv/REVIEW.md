## 1. Executive Summary & Architecture Scorecard

**PiliPlus-LemonTeaV** (`com.lemontea.piliplus.tv`) layers a complete 10-foot Android TV user experience onto `lemonteaau/PiliPlus` without forking upstream business pages. Instead of scattering TV conditionals across 40+ pages, all TV behavior is concentrated into a **Three-Tier Decoupled TV Control Layer**:

1. **Tier 1 — Self-Contained TV Module (`lib/tv/*` & `TvBridge.kt`, 5,643 LOC)**: Owns platform detection, first-run Hive defaults, on-demand IME gating, 2D spatial focus traversal, zero-rebuild focus ring rendering, modal/popup/inline-sheet (`MiniScaffold` / `BottomSheetLayout`) focus promotion & isolation, route focus memory, and the 10-foot video player HUD.
2. **Tier 2 — Build-Time SDK & Material Patches (`lib/scripts/tv_*.patch`, 4 patch files)**: Adapts `GestureDetector`, `RadioGroup`, and `InkResponse` under `NavigationMode.directional` at build time (`patch.ps1` in CI, `tool/tv_patch.sh` locally), keeping `git diff` across upstream UI pages at zero.
3. **Tier 3 — Ultra-Thin Upstream Micro-Hooks (`< 30` lines across 5 Dart files + Android manifest/identity)**: Mounts `TvPlatform`, `TvNavigation`, `TvNavigationObserver`, `TvPlayerHud`, Ethernet broadband recognition, and fork release update URLs.

## 2. Component-by-Component Deep Review

### 2.1 Platform Detection, Defaults & Soft-Keyboard Gate
* **Files**: [`lib/tv/tv_platform.dart`](../../lib/tv/tv_platform.dart) (261 LOC), [`android/app/src/main/kotlin/com/example/piliplus/TvBridge.kt`](../../android/app/src/main/kotlin/com/example/piliplus/TvBridge.kt) (122 LOC)
* **Strengths**:
  1. **Memory-Safe Native Channel**: `TvBridge` wraps `Activity` in `WeakReference<Activity>` and guards every `MethodChannel` call (`getTvEnvironment`, `isTelevision`, `showSoftKeyboard`, `hideSoftKeyboard`) with safe defaults when the `Activity` has been collected across configuration changes.
  2. **Compile-Time & Runtime Flexibility**: `TvPlatform.initialize()` supports `--dart-define=PILI_FORCE_TV=true` and `--dart-define=PILIPLUS_TV=true` overrides for automated tests and desktop/mobile debugging, while safely catching `MissingPluginException` / `PlatformException` on non-Android hosts.
  3. **Idempotent First-Launch Seeding**: `seedDefaultSettings(Box setting)` writes 13 TV-optimal preferences (landscape orientation, side navigation rail, dark theme, `1.2x` text scale, `300dp` recommend card width, auto-play, auto-fullscreen, hardware decoding) guarded by `tvDefaultsSeededV1` and `!setting.containsKey(entry.key)`, guaranteeing existing user preferences are never clobbered.
  4. **Subtle Soft-Keyboard Gate Handoff (`_TvTextInputGateControl`)**: Registering a custom `TextInputControl` suppresses `EditableText`'s automatic `TextInput.show` during D-pad focus movement (`consumeKeyboardToken()` + `TextInput.hide`). When the user explicitly presses `Select`/`Enter`, `requestSoftKeyboard()` sets `_unlockedNode` to `editable?.widget.focusNode ?? node` **before** calling `editable.widget.focusNode.requestFocus()`. Because `requestFocus()` fires `_handlePrimaryFocusChanged()` synchronously when moving focus from an outer wrapper `Focus` to the inner `EditableText` `FocusNode`, pre-assigning `_unlockedNode` prevents premature re-locking—a subtle lifecycle race handled cleanly.

### 2.2 Spatial Focus Engine, Overlay & Route Observer
* **File**: [`lib/tv/tv_navigation.dart`](../../lib/tv/tv_navigation.dart) (3,481 LOC)
* **Strengths**:
  1. **Single-Pass Ancestor & Clip Introspection (`_TvTraversalCache.evaluateNode`)**: Evaluates each candidate `FocusNode` once per traversal pass and memoizes `_TvNodeMeta`. Walks ancestor `Element`s in a single pass to reject hidden `Visibility`, `Offstage`, zero-opacity (`Opacity < 0.01`), `IgnorePointer`, `ExcludeFocus`, occluded `BottomSheetLayout` slots (`BottomSheetType.body` when a `MiniScaffold` sheet is open, or `BottomSheetType.bottomSheet` once `AnimationStatus.reverse`/`dismissed` begins), collapsed `RenderAnimatedSize` / `RenderCustomSingleChildLayoutBox` subtrees, and slide-translated widgets clipped out by `RenderClipRect` / `RenderClipRRect` / `RenderClipPath` (such as `AppBarAni`), while maintaining dual scroll-order (`rect`) and screen-space (`visualRect`) coordinates for pinned/floating sliver headers (`RenderSliverSingleBoxAdapter` / `RenderSliverPersistentHeader` such as `SliverPinnedHeader` and `SliverFloatingHeaderWidget`) so pinned comment sort buttons (`按热度`) never hijack upward D-pad scrolling yet still support clean scroll-reveal to `precedingScrollExtent` and directional exits (`Up`/`Down`/`Left`).
  2. **Offscreen `PageView` / `TabBarView` / `KeepAlive` Isolation (M7)**:
     - `_canUserScroll(ScrollableState)` distinguishes user-scrollable lists/grids from controller-locked `NeverScrollableScrollPhysics`, `PageScrollPhysics`, and `PageMetrics` viewports (`MainApp`'s `PageView` and `HomePage`'s `TabBarView`).
     - `_ensureVisibleInUserScrollables` scrolls only user-scrollable ancestors, preventing focus transitions from dragging a locked `PageView` onto an offscreen tab, and uses minimal-scroll `keepVisibleAtEnd` + `keepVisibleAtStart` on non-directional focus restoration so already-visible cards keep their exact scroll offset.
     - `_isKeptAliveOffscreen` inspects `RenderOffstage`, `KeepAliveParentDataMixin.keptAlive`, and `RenderSliverFillViewport` + `PageMetrics` (`(page - pd.index!).abs() > 0.5`), while `evaluateNode` intersects inner `ListView` viewports against outer non-user-scrollable viewports—preventing kept-alive pages like `MinePage` (`我的`) from retaining phantom offscreen focus after pressing Return.
     - `findRecoveryFocus` recovers invalidated offscreen focus onto visible content inside the same non-user-scrollable container (`HomePage` cards) rather than falling back to the global top-left `userAvatar` (`_mainController.toMinePage`), and `_preferPrimaryInitialCandidates` ensures initial/recovery focus prefers primary card containers over micro secondary buttons (`回复`/`点赞`) of partially scrolled-off cards.
  3. **Algorithmic Scaling in Large Grids (F2, F3, F4)**:
     - Opposite half-plane geometric rejection (`_isInOppositeHalfPlane`) culls candidates behind the movement vector before ancestor tree walks.
     - Pre-computed `adjacentColumnSpans` intervals and bounded micro-action filtering ($O(M \cdot N)$ where $M \approx 0$ for icons $\le 36 \times 36$ or area $\le 2500$) keep traversal latency deterministic (`~3.2ms` mean, `< 50ms` worst-case bound under 120-card grids).
  4. **Self-Contained `MediaQuery`, `showMenu` & Multi-Layer `MiniScaffold` Sheet Lifecycle (M6, M9, M9.5)**:
     - `_unwrapMediaQueryChild` unwraps upstream `MyApp._builder`'s inner `MediaQuery` copy (which carries raw `View.of(context)` `NavigationMode.traditional`) and injects `NavigationMode.directional` directly beneath it—preserving `TextScaler.noScaling` across routes and `showDialog` overlays with **zero diff in `lib/main.dart`**.
     - `_promotePopupMenuFocusIfNeeded` detects modal sibling `FocusScopeNode`s pushed with `requestFocus: false` (upstream `PopupListTile` / `showMenu`) and promotes focus into the popup menu without modifying upstream `popup_menu.patch`.
     - LIFO `_trackedBottomSheetLayouts` + `Expando<_MiniScaffoldSheetRecord>` + `HardwareKeyboard` Select/Enter observation promote focus into newly opened `MiniScaffold` inline sheets (`评论详情`, nested `对话列表`, `选集`, `AI总结`, `视频看点`), wait cleanly across `AnimationStatus.forward` zero-height initial frames and async-loading states (`_subtreeHasRequestableFocus`) without leaking focus to the left video column, preserve the `~0.001ms` `isStationary` fast-path once settled, step into embedded comment actions (`ReplyItemGrpc` `回复`/`查看对话`/`点赞`/`点踩`) via `embeddedCardActionFallback` while keeping 1-card vertical D-pad navigation, isolate zero-focusable sheets (`ImageGridView`), and restore the exact pre-sheet `FocusNode` on Back—with **zero diff in `mini_scaffold.dart` or `reply_reply`**.
  5. **Zero-Rebuild Overlay & Frame-Paced Input (F1, M7)**:
     - `TvNavigation.child` sits inside an isolated `RepaintBoundary`, while `_TvFocusRingPainter` repaints on a sibling layer driven by `ValueNotifier<Rect?>`.
     - `_syncFocusRectAfterLayout` caches `(node, targetBox, targetSize, rootSize, parentDataOffset, scrollOffset)` using an $O(D)$ zero-matrix-allocation ancestor walk (`_accumulatedParentOffset`), reducing stationary per-frame cost during 60/120fps video playback to `~0.001ms`.
     - Replacing `traversalLockedThisFrame` with `repeatLockedThisFrame` throttles held `KeyRepeatEvent`s (one step per frame + 45ms floor) without dropping rapid discrete `KeyDownEvent` bursts, while `ensureVisualUpdate()` prevents `SchedulerPhase.idle` frame starvation.

### 2.3 10-Foot Video Player HUD
* **File**: [`lib/tv/tv_player_hud.dart`](../../lib/tv/tv_player_hud.dart) (1,779 LOC)
* **Strengths**:
  1. **Zero-Coupling Controller Discovery**: Resolves `PlPlayerController`, `VideoDetailController`, `UgcIntroController`, `PgcIntroController`, and `LiveRoomController` dynamically via `Get.isRegistered` and element-tree tag inspection (`heroTag`), allowing a 4-line wrapper in `player_focus.dart` to power UGC videos, Bangumi/PGC episodes, and Live rooms.
  2. **Decoupled Scrubbing (`_virtualSeekTarget`, F7)**: Accumulates rapid Left/Right D-pad seek presses (`< 450ms` cadence) with `1x (10s) → 2x (20s) → 3x (30s)` progressive acceleration against a virtual target position rather than lagging hardware decoder timestamps, committing cleanly and resetting after 1,400ms of inactivity.
  3. **Hold-Select for 3.0x Temporary Playback Speed (M7)**: Disambiguates short press (`< 250ms` without repeat → toggle play/pause or enter fullscreen) from hold (`>= 250ms` timer or `KeyRepeatEvent` → `_pl.setLongPressStatus(true)` `'3.0倍速中'`, `KeyUpEvent` → `_pl.setLongPressStatus(false)`) across fullscreen closed playback, fullscreen Play/Pause pill, and split-screen Quick Strip pills.
  4. **Localized State & Modern Back Navigation (F6, F8)**: Avoids wrapping the player subtree in `Obx`, uses `PopScope(canPop: !_hudVisible)` so Android Back dismisses HUD chrome before popping the route, and consolidates all 5 modal pickers (Episodes, Quality, Speed, Video Fit, Danmaku Settings) through `_showTvDialog`.

### 2.4 Build-Time SDK & Material Patches
* **Files**: [`lib/scripts/tv_gesture_detector.patch`](../../lib/scripts/tv_gesture_detector.patch), [`lib/scripts/tv_radio_group.patch`](../../lib/scripts/tv_radio_group.patch), [`lib/scripts/tv_ink_well.patch`](../../lib/scripts/tv_ink_well.patch), [`lib/scripts/material/tv_ink_well.patch`](../../lib/scripts/material/tv_ink_well.patch), [`lib/scripts/patch.ps1`](../../lib/scripts/patch.ps1), [`tool/tv_patch.sh`](../../tool/tv_patch.sh)
* **Strengths**:
  1. **Zero Touch-Mode Overhead**: Every patch checks `MediaQuery.maybeNavigationModeOf(context) == NavigationMode.directional`. On phones and tablets (`NavigationMode.traditional`), widget trees and gesture arenas behave identically to stock Flutter.
  2. **Static Closure Elimination (`tv_gesture_detector.patch`)**: Uses static `_handleDirectionalKeyEvent` and `_GestureDetectorDirectionalFocus` (with a 650ms hold timer for `onLongPress` that suppresses duplicate `onTap` on release) so hundreds of `GestureDetector` cards on home grids gain D-pad focus and activation without per-build closure allocations.
  3. **Critical Upstream Flutter Bug Fix (`tv_ink_well.patch` & `material/tv_ink_well.patch`)**: Beyond synthesizing center-widget `TapDownDetails`/`TapUpDetails` on `Select`/`Enter` (which powers `ActionItem` hold-to-triple-like and coordinate-anchored `PopupListTile` menus), the patch fixes a stock Flutter Material bug in `_InkResponseState._canRequestFocus`:
     ```dart
     // Stock Flutter bug: returned hardcoded `true` in directional mode,
     // allowing disabled InkWells or canRequestFocus: false wrappers to steal focus!
     NavigationMode.directional => enabled && widget.canRequestFocus,
     ```
  4. **Reversible Developer Ergonomics**: `./tool/tv_patch.sh {apply|revert|status}` mirrors `lib/scripts/patch.ps1` across all 38 patches (28 Flutter SDK + 1 pub-cache + 9 local `material_ui`) so developers never accidentally commit dirty state.
